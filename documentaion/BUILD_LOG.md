## Supplied audit — scoped minimatch remediation and decoder limitation

The full owner audit identifies two root dependency paths. GHSA-g3hv-75wg-m249 affects minimatch 7 through 11.0.0 and is patched in 11.0.1. Expo's fingerprint module uses `Minimatch` construction, `.pattern`, `.negate` and `.match`; TypeScript ESLint uses the named `minimatch` function with `dot: true`. Reviewed the patched package's CommonJS/ESM exports, Node engine range and those consumer calls. Added overrides only under `@expo/fingerprint` and `@typescript-eslint/typescript-estree`, plus Node tests exercising fingerprint ignore/negation behavior and the parser's resolved matching API. Other minimatch dependency paths are not globally overridden. These checks require owner execution; an updated audit result is not yet available.

The decoder advisories GHSA-vcc3-ghjq-m6fr and GHSA-qr28-fpjm-wq7f require `decode-uri-component@0.5.1`. That package is ESM-only with a default function export; Router's `query-string@7.1.3` requires a callable CommonJS export. Modern query-string also changes its export shape, while SDK 57 Router uses a namespace import's `.stringify`. A blanket version override would break those contracts. Kept this path explicitly unresolved pending a compatible upstream fix or a separately tested Router/SDK migration. No audit suppression or forced Expo downgrade/Router major upgrade was introduced.
